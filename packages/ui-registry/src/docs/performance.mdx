# Performance Optimization

Performance optimisation strategies for shadcn-storybook-registry.

## Tree-Shaking

**Tree-shaking** is an optimisation technique that removes unused code from the bundle.

### How It Works

Vite and Webpack analyse the static structure of ES Modules and remove unused exports:

```typescript
// ✅ Good: Named exports (tree-shakeable)
export function Button() { /* ... */ }
export function Dialog() { /* ... */ }
export function Card() { /* ... */ }

// Usage: importing only Button excludes the rest from the bundle
import { Button } from "@/components/ui";
```

```typescript
// ❌ Bad: Default export with object (not tree-shakeable)
export default {
  Button: function Button() { /* ... */ },
  Dialog: function Dialog() { /* ... */ },
  Card: function Card() { /* ... */ },
};

// The entire object is included in the bundle
import Components from "@/components/ui";
const { Button } = Components;
```

### Tree-Shaking in shadcn/ui

shadcn/ui **splits components into individual files**, providing optimal tree-shaking:

```bash
src/components/ui/
├── button.tsx          # Button can be imported on its own
├── dialog.tsx          # Dialog can be imported on its own
├── card.tsx            # Card can be imported on its own
└── ...
```

```typescript
// ✅ Only the required components are included in the bundle
import { Button } from "@/components/ui/button";
import { Card } from "@/components/ui/card";

// Dialog is excluded from the bundle
```

### How to Measure

```bash
# Production build
npm run build

# Analyse bundle size
npm run build -- --analyze

# Or Vite Bundle Visualizer
npm install -D vite-bundle-visualizer
```

### Best Practices

```typescript
// ✅ Good: Named imports
import { Button, Card } from "@/components/ui";

// ✅ Good: Import individual files
import { Button } from "@/components/ui/button";
import { Card } from "@/components/ui/card";

// ❌ Bad: Wildcard import
import * as UI from "@/components/ui";

// ❌ Bad: Import the whole index
import UI from "@/components/ui";
```

## Lazy Loading

**Lazy Loading** is a technique for loading components dynamically at the point they are needed.

### React.lazy()

```typescript
import * as React from "react";

// ✅ Lazy loading
const HeavyChart = React.lazy(() => import("@/components/heavy-chart"));

function Dashboard() {
  return (
    <React.Suspense fallback={<Skeleton className="h-[400px]" />}>
      <HeavyChart data={data} />
    </React.Suspense>
  );
}
```

### Route-based Code Splitting

Next.js automatically performs per-page code splitting:

```typescript
// app/dashboard/page.tsx - automatic code splitting
export default function DashboardPage() {
  return <Dashboard />;
}

// app/settings/page.tsx - separate bundle
export default function SettingsPage() {
  return <Settings />;
}
```

### Dynamic Import with Next.js

```typescript
import dynamic from "next/dynamic";

// ✅ SSR disabled + lazy loading
const Chart = dynamic(() => import("@/components/ui/chart"), {
  ssr: false,
  loading: () => <Skeleton className="h-[400px]" />,
});

function Analytics() {
  return (
    <div>
      <h1>Analytics</h1>
      <Chart data={data} />
    </div>
  );
}
```

### Component-level Splitting

```typescript
// ✅ Conditional rendering + lazy loading
function UserProfile() {
  const [showSettings, setShowSettings] = React.useState(false);

  // Load Settings only when needed
  const SettingsPanel = React.lazy(() => import("./settings-panel"));

  return (
    <div>
      <Button onClick={() => setShowSettings(true)}>Settings</Button>
      {showSettings && (
        <React.Suspense fallback={<Skeleton />}>
          <SettingsPanel />
        </React.Suspense>
      )}
    </div>
  );
}
```

### Where to Apply

Lazy Loading is recommended for the following components:

- 📊 **Chart**: The recharts library is large (100KB+)
- 📝 **Rich Text Editor**: Editor libraries (200KB+)
- 🗺️ **Map**: Map libraries (500KB+)
- 📁 **File Uploader**: File-handling libraries
- 🎨 **Color Picker**: Colour selection UI

### How to Measure

```typescript
// Measure loading time with the Performance API
const startTime = performance.now();

const HeavyComponent = React.lazy(() => {
  return import("./heavy-component").then((module) => {
    const endTime = performance.now();
    console.log(`Loaded in ${endTime - startTime}ms`);
    return module;
  });
});
```

## React.memo()

**React.memo()** is a higher-order component that skips re-rendering when props have not changed.

### Basic Usage

```typescript
import * as React from "react";

// ✅ Wrap with React.memo
const ExpensiveComponent = React.memo(function ExpensiveComponent({
  data,
}: {
  data: string;
}) {
  console.log("Rendering ExpensiveComponent");
  return <div>{data}</div>;
});

function Parent() {
  const [count, setCount] = React.useState(0);
  const data = "Static data";

  return (
    <div>
      <Button onClick={() => setCount(count + 1)}>Count: {count}</Button>
      {/* ExpensiveComponent does not re-render even when count changes */}
      <ExpensiveComponent data={data} />
    </div>
  );
}
```

### Custom Comparison Function

```typescript
// ✅ Custom comparison function
const UserCard = React.memo(
  function UserCard({ user }: { user: User }) {
    return <Card>{user.name}</Card>;
  },
  (prevProps, nextProps) => {
    // Returning true skips the re-render
    return prevProps.user.id === nextProps.user.id;
  }
);
```

### When to Use It?

```typescript
// ✅ Good: Components with expensive computations
const HeavyList = React.memo(function HeavyList({ items }: { items: Item[] }) {
  const processedItems = items.map(expensiveCalculation);
  return <div>{processedItems}</div>;
});

// ❌ Bad: Simple components (only adds overhead)
const SimpleButton = React.memo(function SimpleButton({ label }: { label: string }) {
  return <button>{label}</button>;
});
```

### Ensuring Props Stability

```typescript
function Parent() {
  const [count, setCount] = React.useState(0);

  // ❌ Bad: Creates a new object every time (invalidates memo)
  const user = { name: "John" };

  // ✅ Good: Stabilise with useMemo
  const user = React.useMemo(() => ({ name: "John" }), []);

  // ❌ Bad: Creates a new function every time (invalidates memo)
  const handleClick = () => console.log("Clicked");

  // ✅ Good: Stabilise with useCallback
  const handleClick = React.useCallback(() => {
    console.log("Clicked");
  }, []);

  return <UserCard user={user} onClick={handleClick} />;
}
```

## useMemo() & useCallback()

**useMemo** and **useCallback** memoise values and functions to prevent unnecessary recalculation.

### useMemo()

```typescript
import * as React from "react";

function SearchResults({ query, items }: { query: string; items: Item[] }) {
  // ✅ useMemo: Cache the result of an expensive computation
  const filteredItems = React.useMemo(() => {
    console.log("Filtering items...");
    return items.filter((item) =>
      item.name.toLowerCase().includes(query.toLowerCase())
    );
  }, [query, items]);

  return (
    <div>
      {filteredItems.map((item) => (
        <Card key={item.id}>{item.name}</Card>
      ))}
    </div>
  );
}
```

### useCallback()

```typescript
function Parent() {
  const [count, setCount] = React.useState(0);

  // ✅ useCallback: Stabilise the function reference
  const handleClick = React.useCallback(() => {
    console.log("Clicked");
  }, []);

  // The handleClick reference stays the same even when count changes
  return (
    <div>
      <Button onClick={() => setCount(count + 1)}>Count: {count}</Button>
      <MemoizedChild onClick={handleClick} />
    </div>
  );
}

const MemoizedChild = React.memo(function Child({
  onClick,
}: {
  onClick: () => void;
}) {
  console.log("Rendering Child");
  return <Button onClick={onClick}>Click me</Button>;
});
```

### When to Use It?

```typescript
// ✅ Good: Expensive computation
const expensiveValue = React.useMemo(() => {
  return items.reduce((acc, item) => acc + item.value, 0);
}, [items]);

// ❌ Bad: Simple computation (only adds overhead)
const simpleValue = React.useMemo(() => {
  return a + b;
}, [a, b]);

// ✅ Good: Functions passed to children (together with React.memo)
const handleClick = React.useCallback(() => {
  console.log("Clicked");
}, []);

// ❌ Bad: When the child is not memoised
const handleClick = React.useCallback(() => {
  console.log("Clicked");
}, []);
<NonMemoizedChild onClick={handleClick} />
```

## Virtual Scrolling

**Virtual Scrolling** displays large volumes of data efficiently by rendering only the visible area.

### React Virtuoso

```typescript
import { Virtuoso } from "react-virtuoso";

function VirtualList({ items }: { items: Item[] }) {
  return (
    <Virtuoso
      style={{ height: "400px" }}
      data={items}
      itemContent={(index, item) => (
        <Card key={item.id}>
          {item.name}
        </Card>
      )}
    />
  );
}
```

### Tanstack Virtual

```typescript
import { useVirtualizer } from "@tanstack/react-virtual";

function VirtualList({ items }: { items: Item[] }) {
  const parentRef = React.useRef<HTMLDivElement>(null);

  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50,
  });

  return (
    <div ref={parentRef} style={{ height: "400px", overflow: "auto" }}>
      <div
        style={{
          height: `${virtualizer.getTotalSize()}px`,
          position: "relative",
        }}
      >
        {virtualizer.getVirtualItems().map((virtualItem) => (
          <div
            key={virtualItem.key}
            style={{
              position: "absolute",
              top: 0,
              left: 0,
              width: "100%",
              height: `${virtualItem.size}px`,
              transform: `translateY(${virtualItem.start}px)`,
            }}
          >
            <Card>{items[virtualItem.index].name}</Card>
          </div>
        ))}
      </div>
    </div>
  );
}
```

### Where to Apply

- 📋 **Long Lists**: 100 or more items
- 📊 **Table**: Large volumes of row data
- 💬 **Chat Messages**: Infinite-scroll chat
- 📁 **File Explorer**: Large numbers of files/folders

## React 18/19 Optimizations

Take advantage of the new optimisation features in **React 18/19**.

### useTransition()

```typescript
import * as React from "react";

function SearchBox() {
  const [query, setQuery] = React.useState("");
  const [isPending, startTransition] = React.useTransition();

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setQuery(value); // Immediate update

    // ✅ Route non-urgent updates through a transition
    startTransition(() => {
      // Heavy search logic
      performSearch(value);
    });
  };

  return (
    <div>
      <Input
        value={query}
        onChange={handleChange}
        placeholder="Search..."
      />
      {isPending && <Skeleton />}
    </div>
  );
}
```

## Best Practices Summary

### DO ✅

1. **Tree-shaking**: Use named exports
2. **Lazy Loading**: Use React.lazy() for heavy components
3. **React.memo()**: Apply only to components with expensive computations
4. **useMemo/useCallback**: Combine with expensive computations and React.memo
5. **Virtual Scrolling**: 100 or more items
6. **Image Optimization**: Next.js Image, lazy loading
7. **Import Optimization**: Import only the functions you need
8. **Concurrent Features**: useTransition, useDeferredValue

### DON'T ❌

1. **Over-optimization**: Overusing memo on simple components
2. **Premature Optimization**: Optimising before measuring
3. **Wildcard Imports**: Avoid `import * as`
4. **Inline Functions**: useCallback is mandatory when the child is memoised
5. **Large Dependencies**: Avoid importing entire libraries
