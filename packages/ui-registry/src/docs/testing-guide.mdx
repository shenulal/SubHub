# Testing Guide

The testing strategy and test-writing guide for shadcn-storybook-registry.

## Testing Strategy

This project is made up of three test layers:

- **Play Functions**: Interaction tests within Storybook
- **Vitest Unit Tests**: Unit tests for component logic
- **Playwright Browser Tests**: E2E tests in a real browser environment

## Play Functions

**Play Functions** in Storybook 9 test component interactions automatically.

### Basic Structure

```typescript
import type { Meta, StoryObj } from "@storybook/nextjs-vite";
import { expect, userEvent, within, waitFor } from "storybook/test";
import { Button } from "@/components/ui/button";

const meta: Meta<typeof Button> = {
  title: "ui/Button",
  component: Button,
  tags: ["autodocs"],
};

export default meta;
type Story = StoryObj<typeof meta>;

/**
 * Tests that the state changes when the button is clicked.
 */
export const ShouldToggleOnClick: Story = {
  tags: ["!dev", "!autodocs"], // 👈 Test-only story
  render: () => {
    const [clicked, setClicked] = React.useState(false);
    return (
      <Button onClick={() => setClicked(!clicked)}>
        {clicked ? "Clicked" : "Click me"}
      </Button>
    );
  },
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);

    // 🎯 Purpose: Verify that the text changes when the button is clicked
    const button = canvas.getByRole("button", { name: /click me/i });
    await expect(button).toBeInTheDocument();

    // Click the button
    await userEvent.click(button);

    // Verify the text change
    await waitFor(() => {
      expect(button).toHaveTextContent("Clicked");
    });
  },
};
```

### Story Naming Convention

Play function stories use the **`Should...`** pattern:

- ✅ `ShouldOpenDialog`
- ✅ `ShouldSelectDate`
- ✅ `ShouldValidateForm`
- ❌ `TestDialog`
- ❌ `CheckValidation`

### Tags Configuration

```typescript
tags: ["!dev", "!autodocs"]
```

- `!dev`: Hidden in Dev mode
- `!autodocs`: Excluded from the Autodocs page

### Common Patterns

#### 1. Button Interactions

```typescript
// Find the button
const button = canvas.getByRole("button", { name: /submit/i });

// Click
await userEvent.click(button);

// Verify the state
await expect(button).toBeDisabled();
```

#### 2. Form Inputs

```typescript
// Find the input
const input = canvas.getByRole("textbox", { name: /email/i });

// Enter text
await userEvent.type(input, "test@example.com");

// Verify the value
await expect(input).toHaveValue("test@example.com");
```

#### 3. Dialog/Popover Opening

```typescript
// Click the trigger
await userEvent.click(canvas.getByRole("button", { name: /open/i }));

// Verify that the Dialog is open
await waitFor(async () => {
  const dialog = await canvas.findByRole("dialog");
  await expect(dialog).toBeInTheDocument();
});
```

#### 4. Select/Combobox

```typescript
// Open the Select
await userEvent.click(canvas.getByRole("combobox"));

// Select an option
const option = canvas.getByRole("option", { name: /option 1/i });
await userEvent.click(option);

// Verify the selection
await expect(canvas.getByRole("combobox")).toHaveTextContent("Option 1");
```

#### 5. Keyboard Navigation

```typescript
// Tab key
await userEvent.tab();

// Enter key
await userEvent.keyboard("{Enter}");

// Escape key
await userEvent.keyboard("{Escape}");

// Arrow keys
await userEvent.keyboard("{ArrowDown}");
```

### Purpose Comments Required

Every Play function must include a `🎯 Purpose` comment:

```typescript
play: async ({ canvasElement }) => {
  const canvas = within(canvasElement);

  // 🎯 Purpose: Verify that validation errors are displayed when the form is submitted
  const submitButton = canvas.getByRole("button", { name: /submit/i });
  await userEvent.click(submitButton);

  // Verify the validation errors
  await waitFor(() => {
    expect(canvas.getByText(/required/i)).toBeInTheDocument();
  });
},
```

### Testing Async Operations

```typescript
// Test the loading state
await userEvent.click(submitButton);

// Verify that the loading spinner is displayed
await expect(canvas.getByRole("status")).toBeInTheDocument();

// Verify the success message after completion
await waitFor(
  () => {
    expect(canvas.getByText(/success/i)).toBeInTheDocument();
  },
  { timeout: 3000 }
);
```

## Vitest Unit Tests

Unit-test component logic with **Vitest**.

### Running Tests

```bash
# Run all tests
npm run test

# Run unit tests only
npm run test:unit

# Watch mode
npm run test:unit -- --watch
```

### Test File Structure

```typescript
import { describe, it, expect, vi } from "vitest";
import { render, screen } from "@testing-library/react";
import { Button } from "@/components/ui/button";

describe("Button", () => {
  it("should render with default variant", () => {
    render(<Button>Click me</Button>);
    const button = screen.getByRole("button");
    expect(button).toHaveClass("bg-primary");
  });

  it("should call onClick handler", () => {
    const handleClick = vi.fn();
    render(<Button onClick={handleClick}>Click me</Button>);

    const button = screen.getByRole("button");
    button.click();

    expect(handleClick).toHaveBeenCalledTimes(1);
  });

  it("should be disabled when disabled prop is true", () => {
    render(<Button disabled>Click me</Button>);
    const button = screen.getByRole("button");
    expect(button).toBeDisabled();
  });
});
```

### Mocking

```typescript
// Mock function
const mockFn = vi.fn();

// Mock module
vi.mock("@/lib/utils", () => ({
  cn: vi.fn((...classes) => classes.join(" ")),
}));

// Timer mock
vi.useFakeTimers();
vi.advanceTimersByTime(1000);
vi.useRealTimers();
```

## Playwright Browser Tests

Test in a real browser environment with **Playwright**.

### Running Tests

```bash
# Run Storybook tests
npm run test:storybook

# Storybook Test Runner
npm run storybook:test
```

### Test Configuration

The Storybook Test Runner runs every Play function automatically.

```typescript
// .storybook/test-runner.ts
import type { TestRunnerConfig } from "@storybook/test-runner";

const config: TestRunnerConfig = {
  async postVisit(page, context) {
    // Additional verification logic
    const element = page.locator("#root");
    await expect(element).toBeVisible();
  },
};

export default config;
```

## Accessibility Testing

Accessibility is verified automatically with the **A11y addon**.

### Configuration

```typescript
// .storybook/preview.ts
export const parameters = {
  a11y: {
    config: {
      rules: [
        {
          id: "color-contrast",
          enabled: true,
        },
      ],
    },
    options: {
      checks: { "color-contrast": { options: { noScroll: true } } },
      restoreScroll: true,
    },
    manual: false,
  },
};
```

### Testing WCAG 2.1 AA Compliance

All components must comply with the following:

- ✅ **Color Contrast**: Minimum ratio of 4.5:1
- ✅ **Keyboard Navigation**: Tab, Enter, Escape, Arrow keys
- ✅ **Screen Reader**: ARIA labels, roles, states
- ✅ **Focus Management**: Logical focus order
- ✅ **Semantic HTML**: `<button>`, `<input>`, `<label>`, etc.

### Keyboard Navigation Testing

```typescript
export const ShouldNavigateWithKeyboard: Story = {
  tags: ["!dev", "!autodocs"],
  play: async ({ canvasElement }) => {
    const canvas = within(canvasElement);

    // 🎯 Purpose: Verify that every interactive element is reachable by keyboard

    // Focus the first element with Tab
    await userEvent.tab();
    const firstButton = canvas.getAllByRole("button")[0];
    await expect(firstButton).toHaveFocus();

    // Move to the next element with Tab
    await userEvent.tab();
    const secondButton = canvas.getAllByRole("button")[1];
    await expect(secondButton).toHaveFocus();

    // Activate the button with Enter
    await userEvent.keyboard("{Enter}");

    // Close with Escape
    await userEvent.keyboard("{Escape}");
  },
};
```

## Best Practices

### 1. Test Isolation

Each test must be independent:

```typescript
// ✅ Good: Independent test
export const ShouldOpenDialog: Story = {
  render: () => {
    const [open, setOpen] = React.useState(false);
    return <Dialog open={open} onOpenChange={setOpen} />;
  },
  play: async ({ canvasElement }) => {
    // Test logic
  },
};

// ❌ Bad: Depends on external state
let globalState = false;
export const ShouldOpenDialog: Story = {
  play: async () => {
    globalState = true; // Affects other tests
  },
};
```

### 2. Clear Assertions

Use clear assertions:

```typescript
// ✅ Good: Clear assertion
await expect(button).toHaveTextContent("Submit");
await expect(input).toHaveValue("test@example.com");
await expect(dialog).toBeVisible();

// ❌ Bad: Unclear assertion
await expect(button.textContent).toBe("Submit"); // Uses the DOM API directly
```

### 3. WaitFor for Async

Use `waitFor` for asynchronous behaviour:

```typescript
// ✅ Good: Use waitFor
await waitFor(() => {
  expect(canvas.getByText(/success/i)).toBeInTheDocument();
});

// ❌ Bad: Fixed timeout
await new Promise((resolve) => setTimeout(resolve, 1000));
```

### 4. User-Centric Queries

Use queries from the user's perspective:

```typescript
// ✅ Good: Role-based queries
canvas.getByRole("button", { name: /submit/i });
canvas.getByRole("textbox", { name: /email/i });
canvas.getByLabelText(/password/i);

// ❌ Bad: Implementation-detail queries
canvas.getByClassName("btn-primary");
canvas.querySelector("#submit-button");
```

## Common Issues

### Issue 1: Element Not Found

```typescript
// ❌ Problem: Element cannot be found
const button = canvas.getByRole("button");

// ✅ Solution: Wait, then find
await waitFor(async () => {
  const button = await canvas.findByRole("button");
  await expect(button).toBeInTheDocument();
});
```

### Issue 2: Timeout Errors

```typescript
// ❌ Problem: Default timeout exceeded
await waitFor(() => {
  expect(element).toBeInTheDocument();
});

// ✅ Solution: Increase the timeout
await waitFor(
  () => {
    expect(element).toBeInTheDocument();
  },
  { timeout: 5000 }
);
```

### Issue 3: Multiple Elements

```typescript
// ❌ Problem: When there are multiple buttons
const button = canvas.getByRole("button");

// ✅ Solution: Use a specific name
const submitButton = canvas.getByRole("button", { name: /submit/i });
const cancelButton = canvas.getByRole("button", { name: /cancel/i });
```
